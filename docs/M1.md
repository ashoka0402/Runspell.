# M1: offline Prompt Studio and authoring prototype

Date: 19 November 2026

Scope: [M1 in the roadmap](../ROADMAP.md#m1--prompt-studio-and-graph-prototype).

## Purpose

Make the M0 contracts usable through a prompt-and-canvas authoring flow inside the existing workspace. This milestone uses deterministic fixtures instead of a model or backend. It does not activate workflows or perform external actions.

Open `/app/#/studio` through the **Prompt Studio** link in the workspace. The separate M0 compatibility page remains available at `/app/#/m0`.

## Intended experience

1. Choose the supported invoice example or enter a request covered by the mock planner.
2. Read the assumptions and any clarification or unsupported-capability message.
3. Build a local draft while the graph reflects accepted, saved operations.
4. Select a node to edit its label or typed configuration; drag nodes to adjust presentation.
5. Request a supported mock revision, review its before/after changes, and explicitly accept or reject it.
6. Inspect missing connections and required permissions. Validating a draft does not connect an account or prove business completion.
7. Cancel, navigate away, or refresh without losing accepted changes. Resume interrupted work explicitly.

The interface must label fixtures, simulated planning, local storage, and unavailable execution accurately. General natural-language interpretation belongs to M3. Real connections and execution depend on M2/M4 and the pending live provider gate.

## Implementation boundaries

- Reuse the existing workflow compiler, action registry, draft revisions, and replay contracts.
- Keep the plain JavaScript workspace and landing page; mount the Studio as an isolated React editor.
- Use installed React Flow and GSAP, with reduced-motion and keyboard support.
- Store graph positions separately from executable workflow configuration.
- Keep the legacy `brisko.workflow.drafts` value intact. Any import requires explicit user action and validation; unsupported legacy modules must not be silently converted into different actions.
- Use a separate `relay.studio.v1` browser-local record. No server persistence, collaboration guarantee, or authenticated workspace isolation is implied.
- Preserve malformed/unreadable stored data rather than automatically resetting it. Surface blocked storage, quota failures, and revision conflicts.
- Use storage revision checks to detect stale local saves and draft revision checks to reject stale semantic proposals. This is a local prototype; a production server must provide transactional concurrency control.
- Do not contact models, Trigger.dev, Steel, invoice portals, notification services, or other action destinations.

## Acceptance checks

| Area | Required behavior |
| --- | --- |
| Prompt support | Supported example yields a valid draft; unsupported requests and missing details are honestly explained |
| Accepted operations | Persisted snapshot/event progress precedes its graph animation; playback is never described as execution |
| Manual edits | Typed configuration is validated; invalid changes do not replace accepted state |
| Suggested edits | Show before/after changes and require acceptance; stale proposals cannot overwrite newer revisions |
| Interruption | Cancellation preserves accepted nodes; refresh/navigation show interrupted work and require explicit resume |
| Replay/reconnect | Duplicate events do not duplicate nodes; missing events require recovery from saved authoritative state |
| Storage | Unreadable data is preserved, failures are visible, stale saves are rejected, legacy drafts remain unchanged |
| Import | User explicitly chooses data to import; unsupported definitions fail without replacing accepted work |
| Browser compatibility | M0 remains usable; Studio mounts/unmounts cleanly and remains accessible on desktop/mobile |
| External effects | No model/provider calls, real activation, or external business actions occur |

## Run locally

```powershell
npm ci
npm run build
npm run preview
```

Open [Prompt Studio](http://localhost:8000/app/#/studio). Reuse an existing server on port 8000 rather than starting a duplicate.

Checks:

```powershell
npm run typecheck
npm test
npm run test:browser
py -m unittest discover -s tests -v
```
